# Guardian council: TORUS-A2b (re-run of the A2 relational-torus gate)

Question: A2 failed narrowly (pooled hits@10 1.91x, AUC 0.735), and 42% of its test queries were structurally unanswerable. How do we re-sample, improve the Layer-2 relational torus inside the paradigm (LUT not matmul, GF(17) digits, coordinates not numbers, PTEX pages), and read the gate once on a fresh test split?

- **Architect**: extend the existing executable spec, don't fork it. `torus_data.py` gets a seeded A2b sampler (degree-constrained split, auxiliary training-only Wikidata relations), `sphere_noleak.py` takes the dataset and output paths, `torus_solve.py` gets the four levers as flags (`--bounce`, `--mix`, `--lvl`, `--calib`) and a `test` mode. The Rust `torus_a` driver gets one `l2pack` subcommand that packs every Layer-2 digit array into 4096x4096 RGBA GF(17) pages with `adam_gf17::pack17` and verifies the roundtrip.
- **Sentinel**: the sampling flaw must be fixed by rule, not by hand: every dev and test entity keeps at least 2 training facts after removal, and every test tail stays a training tail of its relation. The sphere used for lifting, cells and tangents must be rebuilt without the new held-out pairs, tangent links into a held-out pair are dropped, and a lift-only dev run checks for leaks. Dev ablations that fit LUTs on dev use 2-fold cross-fitting; the final model trains on train only, fits its dev LUTs on the whole dev split, and test is scored once.
- **Scholar**: multi-bounce rays are path-ranking in coordinate space: a hit through a tangent neighbour's landing is evidence the head shares the neighbour's relational target (siblings share hypernyms). Dimension mixing makes each relation map a GF(17) function of 2 or 3 coordinates (17^2 or 17^3 LUT per output dim), a strict superset of the per-dim map, with backoff to the per-dim marginal for unseen input combinations. Abstraction levels give coarse-to-fine evidence from the sphere's 64/256/1024 cubemap cells. Calibration is a per-relation 16-bucket monotone (PAV) LUT, score bucket to P.
- **Engineer**: CPU only, 3 Taichi threads, every heavy step in `systemd-run --user --scope -p MemoryMax=10G -p CPUQuota=300% nice -n 15`; score in query chunks so the candidate matrix stays small; Rust built with its own target dir under `data/torus/a2b/`, deleted afterwards; never touch the GPU or `adam-t-sft3`.
- **Pathfinder**: try the levers in the CTO's order and keep only what wins on dev, reporting each step as an ablation row; report storage in digits per entity and the 1T/128 GB projection; if a lever only works by leaving the paradigm (float scoring, dense matmul), say so and don't ship it.

Majority (5/5): Architect's layout, Sentinel's protocol, Scholar's methods, Engineer's resource rules, Pathfinder's reporting rule.

Tie: Scholar wanted the abstraction-level evidence learned on training facts; Sentinel objected that the sphere was laid out by those same training edges, so their cell matches are optimistic. Resolved for Sentinel: the level LUT is fitted on held-out (dev) facts, cross-fitted in dev ablations, exactly like the calibration LUT.
