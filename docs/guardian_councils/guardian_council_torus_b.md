# Guardian council: TORUS-B (unlabeled-ray relation discovery)

Question: A2b's relations came from labels (one fitted transform per labeled relation). How do we test, inside the paradigm (LUT not matmul, GF(17) digits, coordinates not numbers, PTEX pages), whether the ray between two concepts defines the relation, with the relation type erased from placement?

- **Architect**: extend, do not fork. `torus_solve.py` gets `--unlab K` (latent-relation hard EM: E-step assigns each training edge to the best translation prototype, existing `fitT --tm trans` refits prototypes, existing ICM moves positions) plus `--orient`, `--ge`, `--tan`. A new `torus_b.py` holds only what is new: clusterers (EM readout, integer k-modes, coarse hash), density LUT, matched negatives, controls, B1 metrics, composition, direction, A2b comparison, export. Rust `l2pack` is reused unchanged.
- **Sentinel**: the label never enters placement or clustering; it enters only the readout label table and evaluation. Same A2b split and no-leak sphere; no LUT is fitted on dev or test, so dev-mode and test-mode solves are identical. The test is scored once per seed (lock file). Negatives are popularity- and origin-matched; a popularity-only baseline proves the matching works. Shuffled-position, random-ray, metadata and lift-only controls bracket every claim.
- **Scholar**: pure translation prototypes make a relation a point in ray space; k-means over integer rays is k-modes with the circular LUT distance. Translations add, so the telescoping identity makes raw path sums trivial; composition is tested at the prototype level (c_k1 + c_k2). Inverses are negation (-c). NMI against the known labels measures recovery, not novelty; novel clusters are shown unfiltered for inspection.
- **Engineer**: CPU only, 3 Taichi threads, `systemd-run --user --scope -p MemoryMax=10G -p CPUQuota=300% nice -n 15` for every heavy step. The E-step is a Taichi kernel over edges x K x D integer lookups; assignment arrays are preallocated and refreshed in place. Rust built with its own target dir, deleted after.
- **Pathfinder**: report the negative if geometry does not recover relations and diagnose why (hub collapse, typed regions, 2-hop reachability). Do not tune on test; two seeds; labeled-vs-unlabeled and storage reported honestly. If a lever needs leaving the paradigm (float scoring), say so.

Majority (5/5): Architect's layout, Sentinel's protocol, Scholar's readouts, Engineer's resource rules, Pathfinder's reporting rule. No tie.
