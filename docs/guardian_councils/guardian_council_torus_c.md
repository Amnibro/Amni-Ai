# Guardian council: TORUS-C (ray angle and polarity as the relation signature)

Question: TORUS-B showed that unlabeled rays encode relatedness (proximity) but not relation type. How do we give the ray the structure it lacked (proximity separated from relation; angle and polarity as the signature) inside the paradigm (LUT not matmul, GF(17) digits, coordinates not numbers, PTEX pages), and test the CEO's thesis honestly?

- **Architect**: extend, do not fork. `torus_solve.py` gets a proximity/relation subspace split (`--psub`), structural-seed assignment (`--seedf`, `--seedfix`), and per-group edge sets so zero-ray proximity pulls act on dims [0,P) and latent-relation translations on dims [P,D). `torus_b.py` is parametrised (`--dir`, `--data`, relation-subspace dims, angle-code clusterer, residual NMI, polarity, strata) instead of copied. New code is only: `torus_c_data.py` (fresh split), `torus_c_seed.py` (label-free structural roles), and the angle LUTs.
- **Sentinel**: new split (fresh seed, new held-out drawn only from A2b training facts, so no A2b dev/test pair is reused), every held-out entity has >= 2 training facts and the pair is stored once; the no-leak sphere is rebuilt for the new split. Labels never enter placement, seeds or clustering; they enter only the readout tables and evaluation. Structural seeds use directed degree, origin and hierarchy depth, no relation id. Test is scored once per seed behind a lock file. Controls: shuffled positions, random rays, metadata-only, seeds-only, B's frozen config R re-solved on the new split.
- **Scholar**: separating subspaces removes the incentive "related means near" has inside the relation subspace; a ray there is a kind difference, so the relation signature is (angle code, polarity) per T^2: the 17x17 difference cell reduced to 16 direction sectors plus a zero sector, polarity = the half-plane, magnitude discarded. Metadata is a strong baseline (origin x degree reads NMI 0.45), so the headline is residual NMI conditional on the metadata cell plus a seeds-only comparison that measures what the geometry adds.
- **Engineer**: CPU only (GPU belongs to HYBRID-1), 3 Taichi threads, `systemd-run --user --scope -p MemoryMax=10G -p CPUQuota=300% nice -n 15`. Dev models deleted as we go, outputs under `data/torus/c/` stay small, rust target dir in the scratchpad and deleted afterwards, deletions logged.
- **Pathfinder**: order the ideas by cost, run each on dev only, keep what wins by the win rule, report the ones that do not. If angle and polarity do not recover relations, give the ceiling (oracle-seeded, seeds-only, metadata) and the diagnosis. Say where the paradigm was left (build-time floats for the atan2 LUT and histograms, in-RAM int arrays at scoring).

Majority (5/5): Architect's layout, Sentinel's protocol, Scholar's signature and baselines, Engineer's resource rules, Pathfinder's reporting rule. No tie.
