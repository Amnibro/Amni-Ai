# Guardian council: DOCREAD (v6.26.0)

**Architect.** The reader is a standalone Helium tool with one shared document model; every format reader only appends blocks (heading, paragraph, item, row, page, note, field, code) with locators, so retrieval, chunking and output formats are written once. Adam talks to it through a subprocess boundary: a crash or hang in a malformed file cannot take the server down (timeout + exit code).

**Sentinel.** Documents are untrusted input. Passwords reach docread only through the `DOCREAD_PASSWORD` environment of one child process (never argv, never stored, never logged), and a wrong password is refused without retry loops; mailboxes stop at 1000 messages. Every parser bounds indexes, recursion and loop counts: form XObjects nest at most 12 deep with a cycle guard, a page runs at most 5 million content operators and 1 million glyphs, archives read at most 500 entries and 256 MiB of entry data (xz, lzma and 7z decoders stop at 256 MiB of output), and attachments and nested archives recurse at most 4 levels. Passages enter the prompt as quoted material labelled with the file and page, never as instructions. Uploaded files stay in the local experiences store for the session; nothing leaves the machine. Path attachments obey the skill registry's allowed roots. Encrypted PDFs open only with the empty user password; nothing tries to crack passwords.

**Scholar.** PDF text follows ISO 32000-2: xref streams and hybrid files, object streams, Standard security handler R2-R6 (Algorithm 2.B for R6), ToUnicode CMaps with bfrange arrays, Identity-H composite fonts, glyph names through the AGL rules, TJ kerning, ActualText. Reading order follows Breuel's two rules with a topological sort. Retrieval is Okapi BM25 with heading-weighted terms and a bigram bonus.

**Engineer.** Gold specs compile to checked Helium; generated code is verified with vectors and fixtures (Gold once dropped an init call silently). Oracles: pdftotext word F1 on public PDFs, soffice-generated Office fixtures, qpdf/Ghostscript/LibreOffice encrypted fixtures.

**Coder.** Agentic coding runs through Amni-Code, never on the real folder. Each run copies the target into a temporary sandbox outside it (reflink when the filesystem allows, else a capped full copy), starts a per-run Amni-Code in bubblewrap with only the sandbox and its own home writable, gives it docread as an MCP server, validates the copy with the project's own test command inside bubblewrap, and places changed files back only when validation passes and nothing in the target changed meanwhile (all or nothing, atomic per file). New cache and build output is never placed, ignored files never are, a patch is always kept, and the sandbox is deleted in every outcome. Model-initiated calls are forced to plan mode; only the owner can let it edit.

**Pathfinder.** Gaps kept visible: RC4-encrypted legacy Office files (97-2003 and RC4 CryptoAPI) are refused with a warning rather than decrypted; the Agile data-integrity HMAC is not checked; Office decryption runs at about 3.3 MB/s because the AES block decrypt is scalar; the decrypted text of a password-protected upload stays in the session store as a plaintext sidecar until the document is cleared; OCR runs through tesseract when its data is installed (Helium OCR is not written yet); CFF built-in encodings and predefined CJK CMaps without ToUnicode yield a warning instead of text; 7z archives that use AES, PPMd, BCJ2, ARM64 or Deflate64 are listed but not read, and xz filters other than BCJ x86 and Delta are refused. Cross-device targets fall back to a full copy capped at 7 GiB. Next: Helium OCR, a PTEX document store so attached files persist as pages Adam can recall.
