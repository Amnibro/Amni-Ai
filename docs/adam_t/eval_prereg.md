# ADAM-T evaluation: pre-registration (dev suites)

Date: 2026-09-25. Harness: `scripts/adam_t_eval.py`. Seed: `20260925` everywhere. The CEO's bar is "if it can answer questions, that's more than half the battle". Everything below was fixed, and the split files were hashed with `amni.compute.eval_lock` (`data/adam_t/eval/prereg_lock.json`, which also hashes this file), before any model was scored. If this file or a split changes after the lock, every later report is recorded as `dry`, not `prod`.

## Scope and rules

- Dev material only. The harness never reads the locked or held-out sets: nightly NQ (`v20_m13/nq_v20_m13.json`), D2, D3 (`d3/d3.jsonl`), D4, the e2e locked suite, or any chat hold set (`data/chat*/hold_eval.jsonl`).
- CPU only, at most 4 threads (`RAYON/OMP/MKL/OPENBLAS/TI_NUM_THREADS` are capped at 4), `nice 10`. Heavy runs go under `systemd-run --user --scope -p MemoryMax=4G`.
- Third-party models are never run or trained here. Their published numbers appear as reference only.
- Reports go to `data/adam_t/eval/report_<model>_<step>.json` through `eval_lock.record`, which stores the git head, code hashes and split hashes. The markdown table is `data/adam_t/eval/table.md`.

## Model interface

The harness needs two callables: `gen(prompt: str, max_bytes: int) -> str` and `logprob(context: bytes, continuation: bytes) -> float`, which returns the natural-log probability of the continuation. It can also take a batched `lpb([(ctx, cont), ...]) -> [float]` for speed. Each adapter owns its decoding, which is always greedy and stops at the first `\n` or at `max_bytes`. Each adapter also declares a prompt format:

| fmt | closed-book QA / zero-shot | reading comprehension |
|---|---|---|
| plain | `Question: {q}\nAnswer:` | `{title}\n{passage}\n\nQuestion: {q}\nAnswer:` |
| chat | `User: {q}\nAdam:` | `User: {title}: {passage} {q}\nAdam:` |

D3-style dialogues are fed as they are, already rendered as `User:`/`Adam:` text that ends in `Adam:`.

Adapters:

- `--model base`: the hash-field byte LM `BASE_PACK` (`rayhash_clean1v2_base_v18_s100k`) through `adam_ray` on the CPU, fmt `plain`.
- `--model v19`: the v19 memory model `DEFAULT_PACK` (`rayhash_v19j2_clean_chat10j_s30k`), fmt `chat`, using the nightly memory decode (`lock`, `stop_sentence`, `rep=1.0`, no veto).
- `--model proto --proto-cmd "<cmd>"`: any process that speaks the JSON-lines protocol below. This is the ADAM-T path. `scripts/adam_t_eval.py serve --model base` is a reference server for the protocol.

### ADAM-T JSON-lines protocol (stdin to stdout, one JSON object per line; bytes are base64)

| request | response |
|---|---|
| `{"op":"hello"}` | `{"model":"adam-t-<tag>","step":<int>,"fmt":"plain","ctx":<window bytes>,"proto":1}` |
| `{"op":"lp","items":[["<ctx b64>","<cont b64>"],...]}` (at most 64 items) | `{"lp":[<float ln p(cont given ctx)>,...]}` |
| `{"op":"gen","prompt":"<b64>","max":<int>,"stop":["<b64>"]}` | `{"text":"<b64>"}`, greedy, with the stop string excluded |
| `{"op":"bye"}` | `{"bye":true}`, then exit |
| any failure | `{"error":"..."}` |

The model must score the whole continuation. When ctx+cont is longer than its window, it truncates the context from the left and reports its window size as `ctx` in `hello`. Scores must be deterministic.

## Metrics and decision rules

Every accuracy is reported with n, SE = sqrt(p(1-p)/n), chance, and `z = (p - chance) / sqrt(chance(1-chance)/n)`. MC chance is the mean of 1/k: 0.25 for qa, rc and mem, about 0.25 for ARC-Easy, and 0.5 for PIQA.

The primary metric for each suite:

1. qa: `all.gen.hit` and `all.mc.acc_norm`.
2. rc: `gen.hit` and `mc.acc_norm`.
3. mem: `gen.strict` and `mc.acc_norm`.
4. bpb: `clean2_hold.bpb`, plus `stream_hold.bpb` when it exists.
5. zs: ARC-Easy `acc_norm` and PIQA `acc_norm`. `acc` is reported alongside.

Milestones, fixed now, that decide whether ADAM-T is "getting good":

- **S (signal):** qa, rc and mem MC each reach `acc_norm` with z >= 2 over chance.
- **R (reads):** rc `gen.hit` >= 0.30 and rc MC `acc_norm` >= 0.50.
- **M (remembers):** mem `gen.strict` >= 0.50 overall, and mem MC `acc_norm` >= 0.60.
- **K (knows, closed book):** qa `all.gen.hit` >= 0.05 (for scale, SmolLM2-1.7B reports 8.7 on NQ held-out) and qa MC `acc_norm` >= 0.40.
- **Z (zero-shot):** ARC-Easy and PIQA `acc_norm` each with z >= 2 over chance.
- **Beats baseline:** a primary metric beats the hash-field base by more than 2 x the pooled SE, where pooled SE = sqrt(SE_a^2 + SE_b^2).

Smoke runs with `--limit N` or a subset of suites are recorded as `dry` and never count.

## Usage

```
python scripts/adam_t_eval.py prereg                         # one-shot: build dev sets, lock
python scripts/adam_t_eval.py run --model base               # hash-field base
python scripts/adam_t_eval.py run --model v19                # v19 memory model
python scripts/adam_t_eval.py run --model proto --proto-cmd "<adam-t serve cmd>" [--step N]
python scripts/adam_t_eval.py table                          # data/adam_t/eval/table.md
```
